# 人物绑定人工点评界面

把已有原生截图组织成逐项人工点评界面，不启动游戏，也不修改绑定。

```bash
python3 tools/character_review/build.py --evidence evidence/rig_audit_20261017
node --test tools/character_review/model.test.cjs
```

完整交互回归使用开发依赖`linkedom`执行真实页面脚本，不启动浏览器或服务器，也不依赖本地证据与大截图：

```bash
npm --prefix tools/character_review install
npm --prefix tools/character_review test
```

在证据目录打开 `index.html`。需要保留 `locomotion-poses/`、`joint-poses/` 及其清单；骨架叠图和 `motion-previews/` 为可选素材。工具按现有七个人物、七种动作构建49个项目，读取每个动作全部相位和五个方向。HTML内嵌索引，不通过网络请求读取清单。

每项可填写整体判断、四个分项和文字意见；画面意见绑定精确的动作相位与方向，可以附归一化坐标标记。连续移动预览单独显示，强制4.5米/秒的居民跑步明确标为快速移动对照。看过图片不算完成点评，“稍后再看”也不计入已点评。

意见输入后立即写入当前浏览器存储。浏览器拒绝存储时，界面持续提示手动导出，不能显示保存成功。导出JSON包含全部49项、未点评但已写下的意见、原图与骨架叠图来源摘要；文字版用于阅读。将JSON交回聊天即可继续处理。不同浏览器之间用导出、导入继续。

导入先完整校验数据集、项目、帧、状态和坐标。默认按项目补齐尚未填写的内容；同一项目已有意见时保留当前项目，不混入导入文件的同项意见。选择替换时先保存一份旧状态，操作后可立即撤销；用户继续编辑后取消整包撤销，避免抹掉新意见。数据集身份包含原图、叠图和连续预览摘要，重拍后不把旧点评当作当前验收。

生成目录仍在忽略的 `evidence/`，不提交截图、个人意见或导出文件。界面源码保存在本目录，生成时只更新HTML、CSS和JS，不覆盖点评JSON，也不清除浏览器进度。
