# 人物斜跑时的清晰度

用户确认问题是人物本身在斜跑时发糊。用实际主场景、空的正式模型和第三人称镜头复现，测试存档分别放在 `evidence/diagonal_run_20261007/*-save/`。

## 原因与修改

人物在 60 Hz 物理帧移动，镜头原来在每个渲染帧追随人物的物理位置。两次物理更新之间，人物不动、镜头继续移动，人物的屏幕位置来回跳；斜向运动同时影响横纵两个方向。原生记录中，相同物理帧的斜跑屏幕位移中位数为 3.684、最大 3.994 个逻辑像素（1280×720 输出约 2.46、2.66 个图像像素）。

`CameraRig` 的跟随位置改在 `_physics_process()` 更新，与人物和弹簧臂同步。键盘转镜头、鼠标拖动与缩放仍由原来的渲染帧逻辑处理；室内固定视角和 `snap()` 继续沿用。没有开启全场景物理插值，也没有改变人物速度或碰撞。

另固定一个真实 `run` 姿势，拍 0°、45°、90°、135°，分别比较 FXAA 与贴图过滤。FXAA 让头发和衣服边缘发软，关闭这道滤镜、保留既有 4× MSAA。七名人物原来的材质均采用普通 mipmap 过滤；`CharAnim` 初始化时复制材质，启用带 mipmap 的各向异性过滤，保留贴图、着色与共享源资源。斜视角纹理改善较小，运动发糊的主要修复是位置同步。

Godot 的[抗锯齿文档](https://docs.godotengine.org/en/stable/tutorials/3d/3d_antialiasing.html)说明 FXAA 会增加模糊、MSAA 不引入这种模糊；[镜头更新说明](https://docs.godotengine.org/en/stable/tutorials/physics/interpolation/advanced_physics_interpolation.html)说明只跟随物理位置的逐渲染帧镜头会跳动。本轮以实际运行数据和同姿势图为验收依据。

## 验证

- `--only=motion-clarity` 共 6 项：抗锯齿、全部人物过滤、横跑、W+D+Shift 斜跑、正常 3.7 m/s 跑速、切换位置后的镜头复位。新检查先在旧代码失败 4 项，修改后 6 项通过，退出 0，无 SCRIPT ERROR。
- 120 帧上限、60 Hz 物理步进的专项检查：旧版斜跑在相同物理帧之间位移最大 8.037 个逻辑像素，新版为 0。横跑检查也降至 0。允许相机碰撞引起正常取景变化，只检查人物与镜头在同一物理帧内是否相互滑动。
- 正式 Forward+ / Metal 原生截图：四个朝向的同跑姿及真实横跑、斜跑。新版实际渲染记录的相同物理帧位移也为 0。画面与数据在 `before/`、`after/`，固定姿势放大对照为 `before-after.png`；放大只用最近邻，没有添加锐化。
- 按 `shots.gd` 补看 `close_bakery`、`store_in`、`house_wide` 三个标准镜头，输出在 `standard-shots/`；退出0，无 SCRIPT ERROR 或引擎 ERROR。
- 最终独占冻结全量1322项通过、0失败，退出0，190.592秒，无 SCRIPT ERROR；检查结果以 `evidence/diagonal_run_20261007/verification.json` 为准。冻结工程放在本轮临时目录，完成后删除；默认存档摘要复核在同一记录中。

已修改开发工程；`builds/HareMachi.zip` 与 Web 导出没有替换。本轮没有重新生成角色模型或贴图。

导入日志有既有的编辑器 Adaptive 主题缺失提示；专项退出时的 ObjectDB / resources 清理提示在旧版、新版都出现，日志原样保留，不计为人物清晰度检查失败。

全量第一轮1322项通过，但末段曾与另一段猫预览短暂并发，没有计为独占验收。独占重跑中落叶检查偶发失败，人物6项仍全部通过；环境专项单跑23项通过。旧检查把一个0.3秒瞬间的水平净位移当成移动路径，合法的风力1.385、摆动相位3.358可使净位移只有0.000037 m，而三段实际路径为0.452 m。将该项改为连续三段路径后，23项环境检查通过；没有修改环境演出。失败日志、计算与各轮结果保留在同一证据目录，最终独占结果见verification。
