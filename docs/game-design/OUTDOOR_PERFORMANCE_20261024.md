# 室外性能优化（2026-10-24）

本轮保留草地索引复用，并让澪、莲使用现有原生衣物包围盒与空间网格计算。夜间广场在本机最终对照中帧率提高约 10%–20%；白天约持平至提高 3%，走跑路线基本持平。模型细节、草地密度、材质、阴影、视距和 4× MSAA 保留原设置。

## 实测结果

Apple M5 Max，Godot 4.8.dev7.official.c971f93e7，实际引擎启动日志为 Metal 4.0 / Forward+。使用现有 screen 0，不创建虚拟屏幕；每个进程使用独立存档并关闭音频输出。VSync 与帧率上限只在基准副本关闭，正式工程设置不变。

静态机位预热 180 帧、记录 600 个实际渲染帧。游戏时钟暂停，但居民继续漫游与播放动作。走跑在预热后开始，分别记录同一路线的 360 个物理帧（6 秒）；步行 10.750 米，跑步 22.097 米。截图读回和 PNG 编码在计时区间之外。

## 改动与依据

- `GrassField` 的每片草叶从 15 个重复顶点变为 7 个唯一顶点和 15 个索引，十字野花面片从 12 个顶点变为 8 个顶点和 12 个索引。15 种草丛及野花面片按索引展开后的三角形顺序、位置、法线、UV、颜色与旧版摘要完全相同，未减少草叶或三角面。
- 现有 `build_layer_geometry` 原先只对和子启用，现在也对澪与莲启用。原生库二进制、角色源网格、骨骼、动画、衣物约束与容差没有变化。缺少原生库或方法时继续使用原 GDScript；`--native-geometry=off` 保留。
- 在最终 2K 夜景中，澪与莲的包围盒/空间网格构建合计从约 1.35 ms/帧降到 0.10 ms/帧。它只是一部分衣物计算，不能与 GPU 时间简单相加。
- 中间着色器候选出现过移动 GPU 耗时增加，拆分复测没有证明着色器调整有稳定收益，最终撤回四处着色器改动。最终组合的步行、跑步 GPU 中位耗时分别为 5.83、5.77 ms，原版为 5.88、5.84 ms。

基准工具补充了真实 GPU/渲染 CPU 时间、实际出帧数、每位角色的阶段成本和原生截图；修复移动测试提前开始、按固定渲染帧数造成路线不等长、精度舍入以及 motion 输出路径运算优先级的问题。每个变体使用全新存档目录，拒绝与其他 Godot 进程重叠。实际后端由引擎启动日志核实。原始测量 JSON 的旧 `rendering_driver` 字段读的是工程默认值（Vulkan），实际启动为 Metal；工具已将该字段改名为 `rendering_driver_setting`，保留旧记录原样。

## 复现

```bash
python3 tools/performance/run_bench.py \
  --out evidence/outdoor-performance-repeat --screen 0 \
  --resolutions 2560x1440,3456x1932 --only baseline,motion \
  --views street,plaza_day,farm,lake,plaza_festival_night \
  --motion-views street_walk,street_run --frames 600 --settle 180 --ablations ""

python3 - <<'PY'
import os, subprocess, tempfile
with tempfile.TemporaryDirectory(prefix="harumachi-outdoor-check-") as save:
    subprocess.run(["./tools/godot", "--headless", "--audio-driver", "Dummy",
                    "--path", "game", "res://scenes/tests.tscn", "--",
                    "--only=outdoor-render", "--out=/tmp/outdoor-render.json"],
                   env=dict(os.environ, HARUMACHI_SAVE_DIR=save), timeout=600, check=True)
PY
```
