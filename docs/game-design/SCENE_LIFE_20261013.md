## 桥的永久装饰

## 两只猫的连续性

旧场景有六个实际猫模型，只有两个游走控制器；只数控制器会漏掉墙上、长椅和屋内的额外猫。本轮以整棵场景树中的真实 `model_id` 普查为准，最终只保留橘猫和三花猫两只骨架模型。一只在住家附近路肩活动，另一只在南町活动，墙、农园长椅和家里不再额外摆静态猫。

两只猫常规行走速度为0.36米/秒，行走动画随实际位移匹配。雨天与夜间改为同一只猫原地休息、保持呼吸和注意动作，晴天继续路线；不再通过隐藏或重新选出生点替换眼前的猫。玩家离开小镇时暂停该区域动物，返回后继续原位置。抚摸提示跟随真实猫身，不留在旧墙面位置。

首次建立动物或读取不再合法的历史位置仍需要安全落位；这个兼容入口与运行中移动分开。活猫等待阻挡解除时不能调用随机锚点重置。动物状态和随机数流沿用原存档协议。

新增检查先跑旧场景，12项中7项失败；修复后12项全部通过。运行测量覆盖真实固定步移动、转向、让行、动画切换、天气、离开/返回及等待入口：两只猫最大单步为0.04561/0.02401米，累计移动6.79/5.22米，没有用静止模型满足“无闪现”。已有动物、摆放、生活内容、场景打磨和世界行为合计105项复测通过。原生212张动作、地面四面、雨夜、旧墙空缺和屋内无第三只猫的画面已逐组查看；325项原生检查和104个真实蒙皮足底样本通过。真实15秒活动中两猫移动4.34/2.04米，最大单步11.4毫米，没有闪现。两次真实E键均只增加一次抚摸计数，猫的前后位移为0。

证据：`evidence/scene_life_20261013/cats/before.json`、`after.json`、`integrated-final.json`、`cats/verification.json`、`cats/native/animals/all.json`。新增回归在 `game/scripts/tests/cat_continuity_checks.gd`。

## 水面实际生效链路

农园与湖泊共用 `LakesideBuilder/Connected_lake_and_river`。初始材质为 `lakeside_water.gdshader`，用户已选B方案后由 `MaterialChoiceProfile` 替换为 `material_options/water.gdshader`；两者共用 `lakeside_water_surface.gdshaderinc`。本轮修改公共水面实现，避免只改未生效的入口。

旧水面只有两个三角形，最长边546.708米。虽然片元中已有波法线，顶点起伏只发生在远端顶点，近岸没有对应的几何变化。现在只对实际湿区细分，22162个三角形、最长边0.990米，不增加玩家碰撞体，也不重建整张干地区域。

反射仍由实际太阳方向、月球位置和附近真实灯的位置决定。太阳反射指数由84改为24，扩大可见方向范围；保留稀疏碎光，加入强度0.072的破碎波带和稍明确的天空反射，让普通观察角度也能读到运动。水纹由真实渲染时间驱动，默认 `animation_time=-1`；测试用固定时间只用于隔离诊断。保留浅、中、深三档色彩、真实底部深度、石头半湿区及薄小雨环，不依靠强写实镜面表现水。

夜间灯光只引用真实附近灯源，最终材质专项读取到5个已绑定的真实灯位置：四盏桥灯的能量权重为0.35，原岸灯为1.0。普通水岸的正午、日落、夜间和雨天画面已逐张查看：波带与碎光可见，浅水石头和桥影仍能读清，没有整片白镜面或水纹溢到岸上。水、远山和鱼完成20张与基线相同机位的最终四时段复拍及24张细节检查；较早细节中的6张水面灯光图已由最终复拍替代，山形与鱼几何检查仍有效。

原生像素诊断使用同一实际投影区域的开/关配对，太阳、月亮和附近灯反射分别改变35.74%、43.31%、47.63%的水面区域，均通过原有局部性门槛。普通近岸视角使用生产 `TIME` 时钟、`animation_time=-1`，间隔实测0.781秒后77.45%的水面区域像素改变，p99亮度差为0.094。真实时间运动、固定相位运动、小雨环尺度和无方格接缝合计7项全部通过。

制作中保留了两次失败：原诊断相机首张仍受物理插值影响，太阳开/关投影区域不同，不能作为有效对照；关闭诊断相机插值后重拍。随后抓到新增太阳常亮底光让100%的水面区域增亮，移除这项底光，保留受实际太阳方向约束的动态碎光后才通过局部性检查。最终像素证据为 `water_landscape/native-water-lamps/pixel-audit.json`，人工判断见 `water_landscape/lamp-fix-review.json`；前两组未通过结果仍保留。

后续独立复核发现，四盏新增桥灯先加入列表，占满了旧四槽反射数组，把原岸灯挤掉，而且桥灯反射没有乘真实0.35能量比例。第九项新回归先在这版抓到 `expected=5, bound=4` 和缺失权重，再扩容量为8、完整绑定实际5盏灯、分别传入四个0.35和一个1.0。修后9项和既有14项全部通过。

最终15帧水面诊断保留原岸灯对照，并用同一桥灯0/0.35/1.0配对。0.35时的编码像素增量约为全亮的0.410，证明权重实际参与了着色；PNG经过sRGB和色调映射，不把这个比值冒充线性辐射度。7项像素门槛再次通过，20张日夜雨水岸重新拍摄并逐张检查。固定相位的太阳三组白天水面ROI逐像素零差；雨天组也没有超过2色阶的变化。最终灯光证据为 `water_landscape/lamp-fix-review.json`、`native-water-lamps/pixel-audit.json`；较早24张细节继续作为山形和鱼几何证据，水面灯光以新20机位及15帧诊断为准。

## 最远处的山

每张地图以现有 `V19_distant_cliff` 的完整三维体积组成18个宽山脊，分为前10个、后8个两层，围绕地图中心约605—905米布置；按距离层调整低饱和天色和硬边阴影。模型宽轴沿山环切向排列，顶面改为宽缓中心起伏，肩部下沉到远地形以下，保留真实侧面和透视变化。每地图约15万三角面，较最初28个的试放减少约36%。

普通跟随、摆放和拍照相机的地形裁剪仍是210米，普通地形雾仍按原85—190米预算运行。远山单独使用 `distant_mountain.gdshader`：保留真实模型的投影，深度放在裁剪面内的最后一层，使用独立远景天色，避免最远山脊被普通树带雾完全吞掉。普通场景仍保留210米视距预算。远山不投射实体阴影、不增加碰撞，也不改变树带和可走地形。

首轮原生复拍发现宽轴朝向观者、山体过高，远景读成巨型石柱；转正并降低以后，24米自由相机又暴露出过密平顶轮廓像一道墙。最终减少为18个、加入低缓曲线并下沉肩部，复拍小镇和农园四方向的玩家高度与24米自由拍照共16张，加上水岸正午、日落、夜间、雨天画面，逐张确认轮廓是低缓山脊，没有巨石柱、平顶墙、底部露空或盖住近树的问题。

最终16张远山图在 `water_landscape/native-final-detail/`，对照图在 `native-sheets/final-mountains-town.jpg` 与 `final-mountains-farm.jpg`。失败首轮和中间平顶版本保留在 `native-first-pass-environments/` 与 `native-detail/`。这些结果验证当前画面，不替代最终帧时间与GPU性能对照。

## 默认语音与音色检查

默认角色语音音量改为0。新配置、缺省旧配置的回退值、Audio的初始值和应用音量的回退值保持一致；音乐与音效仍按原设置播放。用户已保存的非零语音选择不会被强制覆盖，开始新游戏也保留其明确设置。静音时对话不取得配音时长，不触发音乐压低。

新增8项测试先跑旧值，2项失败；修复后8项全部通过。证据为 `voice_tts/voice-default-before.json` 与 `voice-default-after.json`。

现有正式配音共417段：澪147、莲126、小葵70、和子38、空36。审计发现，四名角色主要依赖固定speaker和逐句自然语言描述，小葵使用既有参考克隆；种子随句子长度和ASR重试变化，情绪又会改变描述。原验收主要检查读字与停顿，未把角色身份一致性作为门槛，且未完整记录模型revision、参考摘要和采样条件。它们是可能让音色漂移漏检的工程原因，不能据此把全部问题归因于某一个模型。

本轮完成九段独立新样本，并复制三段原配音作对照：都使用澪的同组三句短、长、开心文本，两种克隆共用已选合成参考 `mio_B_0.wav` 及准确逐字稿。Qwen两路线六段、IndexTTS2三段和原配音三段统一经Qwen3-ASR复核，12段CER均为0，参考音频逐字稿CER也为0。**这些是机器复核结果，尚未进行人工盲听**；只有澪一个角色、每路线三句，不能外推为五个角色或417段全库已解决音色问题。正式配音未替换。

实测机器为Apple M5 Max、128GB统一内存。Qwen使用既有MLX 8bit缓存，IndexTTS2使用官方独立Python3.11环境、torch/torchaudio 2.8、MPS float32，关闭CUDA kernel和DeepSpeed；Index的文本情绪模型未加载，开心句使用明确情绪向量并设 `use_random=False`。各路线均记录模型revision、参考SHA256、种子和采样条件。采样条件与推理后端不同，因此这是本项目的制作路线对照，不是同等硬件/精度条件下的模型排名。

| 路线 | 三句实际生成耗时，短/长/开心 | 同一编码器对参考的平均余弦 |
| --- | --- | --- |
| 原正式配音 | 历史耗时未记录，本轮不推算 | 0.98160 |
| Qwen CustomVoice当前路线 | 0.30 / 1.21 / 1.04秒 | 0.98327 |
| Qwen Base固定参考 | 0.49 / 1.29 / 1.20秒 | 0.98817 |
| IndexTTS2固定参考 | 22.52 / 43.80 / 204.30秒 | 0.98399 |

上述耗时不含模型加载，IndexTTS2本次加载13.33秒。Index的第三句最终得到5.31秒音频，其中GPT阶段耗时198.36秒；进程栈采样落在MPS的multinomial与同步。保留该真实长尾结果，不能凭这一个样本认定情绪向量是原因或声称发生死锁。说话人余弦只作诊断：同一澪选角的另一句为0.99198，不同角色莲的选角为0.95436，绝对高分不等于人工听感通过，也不能用小样的细微分差宣称模型更自然。

建议先为每个角色固定通过听审的参考音频和逐字稿，再锁定模型revision、运行时及采样参数，记录实际生成条件；将ASR、停顿、响度与角色身份检查一起用于筛选。当前保持默认静音，不自动重录全库。[Qwen官方提供固定克隆条件的复用方式](https://github.com/QwenLM/Qwen3-TTS/blob/main/README.md)，但固定参考或固定种子本身都不能替代听审。
