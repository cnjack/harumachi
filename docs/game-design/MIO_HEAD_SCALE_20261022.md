# 澪头部等比缩小（2026-10-22，v24）

用户要求只缩小头部，保持等比。两张原始游戏设定图约为 6.3～6.4 头身，当前游戏 GLB 的正交参考约 6.0 头身；此前桌面版本约 5.1 头身。上述头高统一按发顶至下巴估读，含头发，不是解剖学测量。对照图和坐标在 `evidence/mio_proportion_audit_20261022/`。

## 实现

- `FaceRig.fittedHead` 将头发、脸、独立耳鼻、眉眼和所有口形的源关键形一起乘以 0.8。每个转头姿态以其原下巴位置为中心，所以五官内部比例、下巴轨迹和托腮接触点保持原值。
- 缩放写入正式 CMO3/MOC3，继续由官方 Editor 导出为 Cubism 4.0，39 参数、58 ArtMesh。原图、纹理、PSD 的像素和源分辨率不变，CMO3 的全部头部关键形保存最终比例；无需网页或 Swift 渲染器额外缩放。
- 身体、手臂、腿、衣服、动作参数和物理文件保持原值。运行文件对比只有 `Mio.moc3` 的摘要改变。相对原始作者布局，最终头部比例为 `0.92 × 0.8 × 0.8 = 0.5888`。
- 固定姿态复拍工具改为直接采样动作保持相位，避免首次切换仍拍到放下状态。该修改只影响离线检查。
- 当前身体正面 `y ≥ 310` 区域与修改前逐像素一致；可见发顶从 y=97 移到 y=131，鞋底位置不变，新头身比约 6.1。

## 验证

证据目录为 `evidence/mio_head_scale_20261022/`。最终测试、原应用运行与打包摘要见 `verification.json`。

- 新增正式 Core 顶点比例测试，旧模型先检出 5 处失败；检查横纵等比和固定下巴/胸口。最终 100 项 Swift 发布配置测试中 96 通过、4 项可选网络跳过，项目检查通过。
- 头部体积检查将原先绝对 8 像素的鼻耳视差阈值改为相对实测头宽的同等比例，保留原验收强度，兼容等比缩放。
- 35 个头部角度、五动作各左/中/右视线及三种身体转面，共 53 张真实 Metal 图已目视检查。包含托腮及加油保持姿势。
- 原桌面来信已更新并重启，窗口内实际显示新头部比例，帧计数持续增长。只使用现有显示器，离线复拍静音且没有启动系统监控或网络客户端。
- 标准网页模型 ZIP 已重打包并逐文件解压核验；本轮未重新启动网页播放器，不能以 ZIP 完整性代替浏览器实际播放验收。

## 后续身体宽度问题

用户随后询问身体是否显胖。本轮仍保留“只缩头”的要求，没有缩放身体。对两张原设定图和新正面进行相同总高度比较：裙摆最大可见宽度占总高度约 0.301 / 0.314 / 0.340，当前裙摆相对两图约宽 8%～13%；可见腰带宽度占比约 0.086 / 0.103 / 0.089，当前值在参考范围内。宽松衣袖与裙摆强化了宽阔感，不宜据此直接压缩整个身体。坐标与暗色衣片测量在 `clothing-widths.json`，不代表皮下身体尺寸。
