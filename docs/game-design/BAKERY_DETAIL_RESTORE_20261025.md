# 面包房细节恢复（2026-10-25）

用户指出第 8 轮面包房比优化前更差，丢失了很多细节。同镜头对照确认了这个问题：原灰泥、旧漆、檐线、窗帘、细窗格和布篷褶皱被替换或压平。上一轮把局部建模整洁度当成了整体美术提升，源文件结构检查没有判断出这种损失。

## 已改回的内容

当前候选直接使用正式 `S02.glb` 的完整网格、原 UV、贴图和窗户陈列。第 8 轮新增的厚窗框、九格玻璃、整片墙板、简化檐板和布篷不再覆盖它。这样恢复了二楼原来的双扇窗、窗帘、窗框木纹、窗下的细檐线、灰泥色差，以及布篷的褶皱和宽包边。原来的百叶窗也重新显示。

`material_light_poc_materials.gd` 删除了墙面颜色重混合和 `textureLod(..., 1.5)` 模糊，保留原 shader 的颜色计算，只调整粗糙度、反光和轻微材质法线。第 8 轮的灯光、树冠、草叶、湖水和木桥继续使用。

`shape/config.json` 将建筑替换关闭，并要求当前显示的面包房保留源资源。Blender 生成器默认也不再生成或启用被否决的建筑替换；只有显式使用 `--experimental-bakery-source` 才进入旧实验。旧候选和第 5–8 轮原图保留为历史，清单标记为因细节损失被否决，不再把它描述为当前改进。正式模型、存档、桌面包和网站没有被改写。

## 防止再次丢细节

新增 `material_light_poc_bakery_guard.gd`，在换材质前记录原资源，并在真正显示的画面中检查五项约束：

1. 原建筑本体处于可见状态，而不是只在恢复检查时临时放回来。
2. 当前绑定原 mesh。
3. 每个面的顶点、法线、索引和 UV 数组保持。
4. 四个材质槽仍使用原底色贴图和颜色参数。
5. 原 shader 的底色赋值和颜色修改操作保持，不能再插入墙面模糊／重混合。

检查先在第 8 轮实际运行：两处近景、四模式共 8 张中，原版和仅灯光的 4 张通过，材质和完整候选的 4 张失败。失败项正是“原建筑没有显示”和“贴图颜色计算被改写”。修复后的同组 8 张全部通过。这里检查的是资源与颜色计算的约束，不能代替对最终画面的美术判断。
