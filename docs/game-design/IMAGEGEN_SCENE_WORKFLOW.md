# 用 imagegen 提高已有游戏场景质量

这套方法来自广场设施、老树与苔藓，以及社区中心、面包房和商店的制作。目标是提高实际可玩的三维场景；概念改绘、材质图片和运行截图分别保存。

## 先用实景确定问题

固定机位、游戏时间、天气、分辨率和人物位置，拍总览、玩家距离近景与主要背面。先描述能看到的问题：地面是否大面积同色、物件是否像孤立摆放的样品、材质是否重复、木作是否缺少连接、植物是否像实心块。场景里已有足够内容时，从整张实景改绘开始，才能一起判断主次、疏密和光影。

改绘的提示词要明确：第一张图片是编辑目标；保留人物身份、建筑尺寸、门口与可识别的店铺特色；只有确实合理的家具位置才作为约束。格局本身有问题时，明确允许移动主家具，并附带用途分区图。画风写成日本 TV 动画的干净线条、平涂、少量硬边阴影和夏日通透光，避免仅用作者名字代替具体要求。提示词和每张参考图的用途必须落档。

## 把改绘拆成可以制作的内容

| 目标 | 游戏中的实现 | 验收方式 |
| --- | --- | --- |
| 木板、梁柱和连接 | 实际厚度、分件、接缝、长轴木纹和局部旧色 | 正反面与两米近景，检查分缝、端面和支撑 |
| 草木层次与透光 | 小叶簇、原生 alpha、错落冠层、真实叶片阴影 | 从树下看天空与地面光斑，批量测透光路径 |
| 绒毛苔藓 | 贴树皮的薄层与逐层稀疏的透明短绒 | 近景轮廓、露出的树皮、风动一致与帧时间 |
| 窗边光和室内明暗 | 真实墙洞、窗框、格栅与合适的实际光向 | 穿窗射线、日夜截图、家具遮挡与阴影 |
| 布篷与织物 | 有褶皱或折边的表面、支架、细织纹和局部色差 | 侧面近景、支架落点、远处纹理稳定性 |
| 陈列和使用痕迹 | 有支持面的托盘、布料、纸张、工具和分组商品 | 实测桌面高度、净空、人物路线和状态变化 |
| 公告与价格 | 手绘插图加真实纸面，文字由游戏字体绘制 | 中文可读性、纸面方向、内容与实际玩法一致 |

imagegen 适合画整体目标、透明植物图集、木纹/织物等色纹和纸上插图。色纹提示词应说明正交、无透视、没有烘焙阴影和反光，循环材质还要说明边缘相接。叶片要直接要求透明背景，保留生成的 alpha。木板分缝、玻璃、水、文字与碰撞由游戏处理；不能让生成模型把这些部分黏成实心物体。

## 广场这轮留下的具体经验

- 薄毛发和一颗颗绿色团块都不足以表达苔藓。最终使用 1–22 毫米的八层表面，向外逐渐稀疏，形成细密绒面；低根集中生长，间隔露出树皮。单张绿色贴图不能表达其厚度。
- 树冠增加层次需要减少连续遮挡，单纯加叶片会更密。九组不等高冠层和透光通道，配合实际 alpha 光线抽样，比面数标签更有用。
- 保留已有良好枝干、UV 和身份，再局部整理。生成失败候选留在试验目录，不能覆盖已验版本；付费生成前明确用途与成本，继续使用原账户。
- 同类问题应一起检查。杉树按整类替换叶簇，近景四种树一起测；墙外地面同时检查四个区域，不能只修用户框出的一个视角。
- 陈设的支撑关系要接入共用审计。用真实支持节点、实际表面高度和测量上限声明桌面支撑，专项与全场摆放普查才能得到一致结论。
- 批量截图要复位室内外光照、镜头模式和人物状态。连续拍摄不同场景时，工具遗留状态会让正确的场景得到错误的验收图片。
- 材质高频细节会在远处闪烁。板缝、细织纹、草叶都需要 mipmap、过滤和基于屏幕导数的细节控制，再用实际移动帧检验。

## 从参考落实到交付

1. 保存“原实景 → 正常场所对照 → 用途分区 → 改绘 → 实现清单”。先确定谁会在这里做什么、什么内容吸引玩家停留，再安排主要家具；布局确定后才验证走线。仅有大块净空和任务道具，不能证明场景适合生活。
2. 先做真实形体、开口和支撑关系，再补材质与小物。复用已验模型与构件，新增碰撞注明所属部分，交互 ID 与存档身份继续保持一致。
3. 回到相同机位比较；再看原图未覆盖的背面、侧面、玩家距离、黄昏和夜景。概念图中好看的光必须在实际场景里出现。窗外明亮画片也要随夜晚变暗。
4. 把结构问题变成检查，先在旧版本或错误候选上证明会失败。测试要测实际表面、射线、碰撞、支撑和通路，视觉仍需亲眼判断。
5. 测真实渲染帧间隔，游戏时钟继续运行并传入移动。记录设备、引擎、分辨率、平均值、p95 与最长帧；局部样本不代表全程性能。
6. 用独立存档与冻结工程做全量、原生截图、导出和解压应用的完整演示。退出 0 且默认存档摘要不变后原子替换唯一桌面包，清理临时包与工程，保留证据。
7. 更新当前状态和制作记录，只提交本轮文件。推送后核对远端提交和 CI，其他任务的未完成修改继续保留。

生产素材必须保存到工程中，不能只留在工具的生成目录。原图、概念图、最终实景、完整提示词、模型来源、测量、失败证据和交付摘要各有明确位置，方便下一轮继续调整。

## 公共空间这一轮补上的经验

- 固定旧家具脚印会把旧问题一起固定。先用真实场所的功能关系比较：社区中心需要交流、阅读、茶水和活动收纳；精品面包房需要选购、咖啡服务、备料、座位与杯碟回收；商店需要常温、冷藏、鲜食和日用分区。平面分区先于改绘，走线验收在后。
- 商品种类、单件尺寸、每排数量和陈列深度要一起设计。同款成组，类别相邻；米袋在低处、瓶罐正面朝外、奶蛋在真实冷柜；每层盘宽决定能放几个面包，不能为了塞进货架把法棍缩成小棒。
- 甜点要先分轮廓，再分颜色。切层草莓、深色巧克力、低矮芝士和圆形水果塔，作为四个独立 imagegen 单物参考转为 3D，统一一人份尺寸。机械咖啡设备、直线柜体和椅桌用精确建模，避免图生模型把玻璃、支架与操作空间黏在一起。
- 图标直接生成透明背景，进入共用 UI 素材库；货架上的中文、价签和菜单由游戏字体绘制，并和实际物品价格核对。
- 用途要落实为可选使用。阅读角能坐下读小志，共用桌能翻街坊小报，茶水可自取，咖啡可以购买后带走或坐着喝，甜点可以在桌面享用。不能用纯摆件暗示不存在的玩法，也不把休息变成额外任务门槛。
- 坐姿、起身与存档是一个整体。按当前骨架命名适配下肢姿势；坐着时暂停角色移动但保留世界运行，起身检查真实碰撞，保存安全站位。测试之外还要在原生近景观察椅面、衣物和脚的位置。
