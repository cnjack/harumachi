# 入场、街坊与动物的运行改造

用户要求改用自动脚本检测，检查出现地点、顺序、运动轨迹和穿模/重叠；动物保留常见活动区，在区内按规律随机；街坊有主要位置，也有日常变化；对白随地点变化，首次认识和当前事情有明确优先级。开场改为下车后过渡回家、过夜，次日起床才自由行动。

## 实施顺序

1. 给真实场景实例登记来源、创建顺序、首次发现、显隐、移动、跳变、移除与碰撞；同一观察器可挂到普通游戏和完整autoplay。另用声明日期/时段夹具遍历日程和集市。观察器只记录，不代玩家移动或修改进度。
2. 复现普通人物、猫和鸟虫的障碍反例。普通行走也要检查完整身体扫掠，堵住时等人或重新规划；不能直接穿过墙、树干或玩家的家具。支撑、手持、坐姿与植物接地按真实归属核验，允许接触不能整类豁免。
3. 新档搬入按持久化阶段编排。实际领取钥匙/便笺、进入家后完成Q00；同一次搬入只换日一次，次日卧室才解锁。保存失败可重试，旧档不重播；首餐仍是玩家次日主动做的事。
4. 猫用各自住宅街活动区的安全锚点、局部目标、停留和避让；鸟虫保留花丛/河岸/草地常见区。各实体独立RNG及状态进入现有数据库，UI和脚步音效不改变动物随机序列；读档不强制重新抽位置。
5. 人物的店铺柜台、节日和对话暂停优先于普通日程；普通生活加入有限的星期/天气例外和近处活动。对白按实际地点选择，首次身份介绍、已认识、小事参与分开记录。重要后续和当前委托用明确候选入口，不能让任意active任务压住所有生活。
6. 相关反例、全量检查、长时间运动扫描、完整主线自动演示和原生疑点截图通过后才更新唯一交付包。自动运行不替代自然四小时或真人乐趣。

## 验收

| 项目 | 必须通过 | 反例或限制 |
| --- | --- | --- |
| 观察器 | 同一真实对象有稳定标识、来源/归属、时序、活动状态、位置和轨迹；记录实际碰撞对象 | 强制安排日期/位置明确标为夹具；首次发现不冒充创建顺序 |
| 穿模/重叠 | 人物/猫的完整身体不得穿SOLID或PLACED；静态支撑和物体占地继续跑PROPS/PLACEMENT | 先让原有未检查行走穿过一个真实测试障碍，确认埋点能发现；不能仅检查配置路径 |
| 入场 | 新局到站→钥匙/便笺→家→一次换日→D2卧室→恢复控制，Q00真实完成 | 每阶段中断/读档不重复钥匙或换日；旧档不自动搬入；保存失败不报成功 |
| 动物 | 多个seed均留在合法活动区、合法支撑/空域；有不同目标/动作；同seed可重放 | 没合法点安全等待；家具/人/另一动物挡住也不能穿过；不要求每次读档重抽 |
| 人物 | 主要地点可预判；新增日程实际可走，店主柜台不被拉走，对话时不换位 | 有完整日程及同时活动的运行证据，不能只force瞬移到配置点 |
| 对白 | 实际地点对应不同内容；初见不假造种菜/赠送/供货；任务与生活候选可选择 | 新合作路线未种番茄时，小葵不能声称玩家会种番茄；旧档不凭空补“我见过你”事实 |
| 保存/发布 | 独立HARUMACHI_SAVE_DIR、默认摘要不变；最新源码全量与解压包autoplay退出0 | builds继续只留最新HareMachi.zip及最多一份web；未知声画/自然时间单列 |
