“未见露底”仅指本轮复核范围。接缝存在于不透明图像的色块与轮廓之间，不能用 alpha 中心点通过来消除这项视觉问题。

## 确定的问题与定位

### 1. 自动说话打断 / 恢复直接跳姿

`PuppetMotion.swift` 的自动分支在 `pose.speaking` 改变时立即改选动作和相位；渲染器的 0.4 秒历史缓动由 `selectGesture` 触发，自动内部切换没有经过这个入口。实际邻帧证据：

| 复现 | 相邻时间（秒） | 右腕位移（750×1000 画布像素） |
| --- | --- | ---: |
| 说话结束恢复招手 | 2.800 → 2.833 | 230.60 |
| 思考被说话打断 | 18.300 → 18.333 | 213.16 |
| 说话结束恢复伸懒腰 | 36.800 → 36.833 | 334.21 |

这些是 33.3ms 内的跳变，画面直接复现，不是因采样间距不同而作的速度比较。应先统一自动与手动动作的过渡状态，再复验打断、恢复和连续多次打断。

### 2. 中途切换绕行过快，同动作重播也先收回

`selectGesture` 把目标动作相位重设为 0，随后在 0.4 秒内将保持姿态混到目标的起手阶段。25 组过程表显示：

- 思考 → 伸懒腰先快速将手甩到腰侧，再往上举，最大单帧右腕位移 91.97 像素（第 8→9 帧）。
- 伸懒腰 → 思考 73.99，思考 → 招手 71.62，招手 → 思考 64.76 像素/帧。
- 招手 → 招手、思考 → 思考、伸懒腰 → 伸懒腰都有明显先收回再开始的过程；即便网格没有翻面，也不代表表演自然。
- 轻摆与说话之间的切换位移小、较稳定；涉及深折肘或高举双臂的组合最明显。

### 3. 不同手型的交叉淡化形成重影

`MetalRenderer.swift` 在预乘 alpha 空间按权重混合放松手、掌心、握拳等源图；它保持了重叠部分颜色，却仍会让两套轮廓不重合的区域半透明。思考的前景手层还单独按 `rightChin` 淡入。

因此生成了可以看见背景的旧长手指、新指向手和双前臂。思考第 15 帧（0.5 秒）、招手与说话的起手、握拳切换均可复现。`switch-think-stretch/0007.png` 的右腕 3×3 邻域最小 alpha 为 190/255；属于过渡半透明问题，未发现完全断开的贯通洞。

应从源手型的共同前臂注册、过渡绘图或手部变形修正，使手掌与手指真正收放；单纯加快淡化仍保留两套轮廓。

### 4. 右肘圆片、肩部裁边和手腕横线

`pack_assets.swift` 将右前臂根部保留为半径 32 的圆区，上臂保留到肘下 25；两片刚性旋转。此源几何切分保证了覆盖，但原衣褶没有为任意折肘重画，故圆弧边界和下缘尖片可见。左臂连续弧形变形，右臂独立旋转，造成伸懒腰时左右衣袖体积不一致。

右肩上臂前片的硬裁边，以及食指手型前景/前臂拆片附近，均有点状线。应优先调整源裁片形状、补齐折肘专用袖子和隐藏边缘、匹配腕部颜色与宽度，再处理必要的绑定残差。不能把扩大覆盖面积当作自然度修复。
