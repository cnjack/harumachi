# 制作计划

## 制作顺序

先明确体验与验收，再做 Godot 灰盒闭环，随后用一组 Hyper3D → Blender → Godot 样件验证资产流程，再批量补充美术。这样能在生成大量素材前发现镜头、比例与玩法不合适的问题。

| 阶段 | 工作与交付 | 进入下一阶段的证据 |
| --- | --- | --- |
| M0 设计 | 本套文档、首个任务链、地图、资产优先级 | 各系统能服务同一个集市目标；关键假设明确 |
| M1 灰盒可玩 | Godot 工程、角色移动、镜头、交互提示、3 个临时 NPC、对话、委托、背包、有限布置、存档 | 从开始到集市结束可完整游玩；退出重进状态保持 |
| M2 模型样件 | 用 Hyper3D 制作 P02 公告栏、P09 摊位、S02 面包店；Blender 清理并导出独立 GLB | 三类样件在 Godot 中比例、材质、碰撞、交互均正确 |
| M3 角色与街区 | 街景模块替换灰盒；角色基础绑定与动画；主角房间；导航及固定日程 | 三位 NPC 可到达安排位置；走动、转角、门口无遮挡卡死 |
| M4 美术与 UI | 光照、天空、材质统一；HUD、对话、背包、任务、布置界面；音效与无障碍设置 | 实机画面保持干燥地面；全部界面可操作；核心交互可辨识 |
| M5 打包验证 | 完整试玩、存档恢复、性能记录、目标平台构建和说明 | 在目标机器上打开导出包，完成任务链并保存；交付录像与已知问题 |

各阶段只在验收后标记完成；提交生成任务、成功导入、编辑器启动都不等于可玩验收。工期在 M1 和 M2 实际完成后按工作量估算，不预先承诺日期。

## 首个可玩版本的边界

一块约 100 × 80 米的街区是初始设计尺寸：主街、居民支巷、公共庭院、公交入口、主角房间。以实机步行节奏调整，入口到任何关键节点目标不超过约一分钟。约 10–12 栋建筑外观中多数不可进入；只有主角房间有室内。

3 位 NPC、5 项一次性委托、约 12 种背包物品、6 种可布置物、2 个布置区域。一个演示作物、三个生长状态，按完成步骤推进，避免等待。只有晴天下午与集市结尾暖光两个表现阶段；结尾也没有湿地面。

角色原型先使用有明确授权的临时胶囊体/自制基础人物。正式人物模型、绑定和动画独立验收，不假定单次生成能够直接成为可控角色。

## 验收用例

1. 新游戏能走到公告栏，距离不够时不会触发远程交互。
2. 接受委托后重复对话不会重复添加；物品不足不能交付。
3. 正确交付只消耗要求物品一次，只发放一次奖励。
4. 关键任务物品不可卖掉或丢失；临时交互取消可返回正常游戏。
5. 物件只放在合法区域；不重叠、不封门；撤销能返还占用。
6. 保存后关闭并重开，人物进度、背包、布置、种植状态与结束标记保持。
7. 集市只在所有必要准备完成时开放；可选装饰不阻塞通关。
8. 快速连按交互、在区域边缘移动、背包满、读档后再次交付均不破坏状态。
9. 键鼠与窗口缩放实测；菜单期间角色停止移动；文字不会超出面板。
10. 导出包在目标机器实际运行并记录性能。1080p、60 FPS 是初始目标，尚无测试结果。

## 风险与处理

生成模型过重：先限制样件复杂度，再减面、压缩纹理、做 LOD。房屋不能正常进入：首版只建一个室内，门口通过场景切换。镜头遮挡：限制俯仰和旋转范围，遮挡屋顶淡出。风格偏写实：重绘基础色，降低材质噪声，统一 Godot 光照。Hyper3D 暂未接入：继续灰盒与设计，接入后沿原方案验证样件，不擅自更换模型服务。

## 交付结构（规划）

`game/` 放 Godot 工程；`art/source/` 放 Blender 源文件；`art/exports/` 放整理好的 GLB；`art/references/` 放参考图；`art/manifests/` 记录来源与生成参数；`builds/` 放导出包；`evidence/` 放实机截图、录像和验证记录。现有 output 素材保留，不直接覆盖。
