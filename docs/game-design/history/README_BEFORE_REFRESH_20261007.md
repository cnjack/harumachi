## 与原计划不同的地方

- **模型服务**：用户一开始指定 Hyper3D，但当时的试用 key 返回 `API_INSUFFICIENT_FUNDS`，经用户同意 v0.1–v0.3 改用腾讯混元 3D `hy-3d-3.1`。v0.4 用户充值后，最差的 5 个模型、新的大树、农园道具和两名新角色用 Hyper3D Rodin Gen-2.5 重做（27 个）。v0.5 按用户要求优先用自建的 Pixal3D（免费），先和 Hyper3D 做了质量对比，差不多才批量用；简单的几何件（木桥、农园大门、路牌、盆舞台、纸灯笼、长桌、收纳箱、供台）直接用 Blender 脚本生成（收纳箱在 v0.6 换成了 Pixal3D 模型）。v0.6 复查时发现 Pixal3D 的模型是在参考图的相机视角下重建的，放进游戏会斜 20–65 度，于是逐个量出朝向转正；玻璃和不锈钢的冷饮柜、冰柜 Pixal3D 做不好，改用 Blender 程序建模加 codex 画的贴图。每个模型在 manifest 里按实际来源记录。
- **视频模型**：用户给了 LTX-2.5（MLX）和 MiniMax-H3 两个本地模型。LTX 的首帧图生视频在本机 1024×576、10 秒一段约 4 分钟，画风和构图都守得住，片头 6 个镜头都用它。H3 试了两条路：原生 Metal 版 `h3.c` 需要的 BF16 transformer 本机没有下载；MLX 版（8-bit transformer）按作者的基准一步去噪就要几分钟，而且它的图片条件分支有两处问题——视觉编码器的卷积权重没转成 MLX 布局（已在本地补了一行 `sanitize`），以及图片占位 token 数和视觉特征数对不上（303 对 220），没有修好。H3 的文生视频能跑：640×352、5 秒、8 步约 2.2 分钟（每步 13 秒），还会同时生成声音；烟花的动态比 LTX 更热闹，但分辨率低，画风偏写实，而且没有关键帧就对不上游戏里的晴町。对比图 `evidence/video_model_compare.jpg`，H3 的样片 `evidence/h3_fireworks_t2v.mp4`。片头当时全部用 LTX 做；用户看过后觉得不够动漫，要求删掉视频，改用 codex 直接画动漫插画，现在的序章是游戏里播放的插画幻灯片。
- **集市时间**：v0.3 准备好就能随时开集市；v0.4 有了时钟，集市固定在周六 16:30 开，第一次集市之后生活继续。
- **引擎版本**：本机 `/Applications/Godot.app` 是 4.8.dev6 开发版，工程改为锁定 **Godot 4.7.2 stable**（`/Users/jack/workpath/godot/tools/godot-4.7.2`），导出模板一致。
- **委托数量**：多了一个引导委托 Q00「搬家第一天」（信箱 → 进家门），教移动和交互。
- **装饰**：v0.1 的“桌布”换成“纸灯笼”，集市时会亮灯。
- **音乐**：第一版音乐是代码合成的。按用户要求换成本地 `/Users/jack/workpath/research/music` 部署的 MiniMax Music 3 生成；音效和环境声仍用合成版。太鼓小游戏需要和谱面逐拍对齐，曲子用代码合成（`art/tools/audio/taiko_song.py`），谱面同时生成。
- **小游戏的制作方式**：先写好统一的小游戏基类和沙盒，再给每个游戏写一份规格，交给 5 个并行的 codex 任务各自在工程副本里实现（代码、画面、自测）。收回后统一修了一处图片尺寸问题（见 [PLAN.md](../PLAN.md)），测试和录像都在 Godot 4.7.2 下重新跑过。

## 已知限制

- 角色动画是脚本生成的程序化动作（走、跑、挥手、张望、蹲下、说话手势、盆舞），不是动作捕捉或手 K 动画；没有坐下、拿东西的动作，看烟花时角色是站在长椅前的。
- 生成模型大多是一整块网格：门、柜门不能开；除玩家的家、商店和面包店以外，建筑都不可进入。
- 平衡只模拟了 30 天（到 8 月初）。8 月中旬以后的节日（灯笼流、月见）能玩，但那时的收入和花销没有逐天模拟；第 30 天之后没有新的大额花销，钱会一直攒下去。
- 节日日期写死在夏天到初秋，没有做季节变化和第二年。
- 音乐是 AI 生成的（MiniMax Music 3 社区 MLX 8-bit 版，受 MiniMax-Music3 Community License 约束，标题画面标明了“音乐：MiniMax-Music3（AI 生成）”）。每首曲子有头有尾，不是无缝循环，游戏里在曲尾前 3 秒交叉淡入重新开始。
- 音效和环境声是程序合成的，不是录音。旁白、春婆婆和田中爷爷没有配音（试听后去掉的）；配音是 TTS 生成的，个别字的读音靠替换表纠正（例如“澪”按“玲”读）。
- 邻居的活动路线是写好的循环，不会临时改主意，也不会互相搭话；和子阿姨的生成网格抬手会变形，所以她只做张望和鞠躬，也不参加盆舞。
- v0.6 第一轮复查模型时 Hyper3D 连不上（当时会话里没有 Rodin 工具），重做用的是 Pixal3D 和 Blender；之后 Hyper3D 的 MCP 工具重新连上，用它重做了小卡车。
- MiniMax-H3 的图生视频没有跑通（见上文“视频模型”）。
- 目标平台、核心方向这两个问题用户一直没回答，本版按文档默认值做：macOS 桌面单机、键鼠、中文。
