# 澪裙摆宽度调整（2026-10-22，v25）

用户认可先收窄裙摆 5%～8% 的建议。本轮将裙摆最宽处收窄 6%，保持 v24 头部比例、腰线与腿部尺寸。

## 源模型

`BodyRig.fittedSkirt` 只供作者端烘焙使用，在下半身动作形变之前调整裙子的横向坐标。腰部 y≤450 保持原位，向下平滑增加收窄量，最宽的下摆为 0.94 倍；到 y=690 网格行恢复原坐标，避免同一 ArtMesh 中的腿、鞋一起缩窄。纵坐标与原图像素不变。

所有下半身源关键形经过相同处理，再由已安装的 Cubism Editor 5.3.04 官方导出。可编辑 CMO3 与正式 MOC3 均包含调整，网页及 Swift 不需要额外缩放。仍为 Cubism 4.0 / MOC version 3、39 参数、58 ArtMesh。

## 验证

证据在 `evidence/mio_skirt_width_20261022/`。

- 正式 Core 顶点回归先用旧模型验证，三种身体转面各检出一处宽度失败。新模型通过，腰部和腿部探针保持原位。
- 101 项 Swift 发布配置测试：97 通过、4 项可选网络跳过，零失败。
- 五种动作各左/中/右视线和三种身体转面，共 18 张真实 Metal 图逐图检查；裙褶、下摆轮廓及膝盖交界未见新增断口。
- 正面裙摆最大可见宽度从 289 像素变为 271 像素，约收窄 6.2%（边缘像素取整）；源网格宽度精确缩小 6%。18 张对应画面的 y<440 与 y≥700 区域逐像素一致，即头部、上身和膝盖以下没有改变。
- 原「澪 · 晴町桌面来信」已更新重启，真实窗口确认新轮廓并持续出帧，Clef 自动连接成功。没有创建新应用或虚拟显示器。
- 标准网页模型 ZIP 同步重打包并逐文件解压核验；本轮未重跑浏览器播放器，不以打包成功代替网页播放验收。

对照图为 `before-after.png`，动作总览为 `motion-contact.png`，完整摘要见 `verification.json`。头部比例调整的历史记录保留在 [v24](MIO_HEAD_SCALE_20261022.md)。
