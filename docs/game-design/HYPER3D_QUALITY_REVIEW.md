# Hyper3D 模型质量与贴图更新（2026-10-02）

本轮从 Blender 程序模型里选了农园门楼、盆舞台和面包店双层烤箱。问题分别是屋瓦和梁柱过简、红白裙布像硬板且屋顶像叠块、烤箱只有纯色块和发光窗口。另处理面包店 S02 的模糊图集，以及 A13 黑板的荞麦面文字和倒置背面。

## 调研结论

Hyper3D 的 `tier`、网格类型、目标面数和贴图设置是独立的。只选 High 并不能保证导出高面数网格：本轮网页门楼样件只有 828 个三角面，因此没有采用。官方说明见 [Rodin Gen-2.5](https://docs.hyper3d.ai/en/api-specification/rodin-gen2-5)。

参考图决定物件设计。先画清楚的单物体图：完整轮廓、适度的 3/4 视角、干净背景、平涂和有节制的细节。复杂或需要看背面的物件，再由同一张定稿编辑出背面图，不能分别随意画两张。接口支持最多五张独立参考图；API 可用 image_label 指定方向，当前 MCP 只接受按顺序上传的图片，导出后仍要检查朝向。

高面数适合保存原稿，不能直接当成游戏质量结论。10 月 2 日的全模型巡检进一步确认，早先 Raw 版本的碎片主要由导出时漏焊 UV 接缝重复顶点导致，不能据此断言 Raw 服务原稿比 Quad 差。百万面 Raw 在减面后可能出现破碎的纹理采样或轮廓细节。本轮盆舞台用同一组图比较 High Raw 100 万面与 High Quad 5 万四边面，两者均制作成约 2.8 万三角面的游戏版本；Quad 版本的布边、红白条纹和屋顶明显更完整，最终采用 Quad。进游戏前需要看低面数结果，不能只看服务预览或原稿面数。

静态道具的贴图只保留底色。生成参考图时不要画很强的反光、投影或字；去光照可以减少烤死的明暗，但不能代替画风验收。Gen-2.5 的 HighPack 提升贴图分辨率，不增加几何。官网 API 文档和当前网页的功能权限不同：本轮网页 4K 导出要求 Business，实际采用 2K 原稿。微观表面细节与 12K 贴图不是本游戏的默认选择。

## 可重复的流程

1. 参考图提示词放 `art/manifests/prompts/`，原图放 `art/references/`。本轮三件物体的正面图和两张背面图由内置 imagegen 生成或编辑，完整提示词分别在 `hyper3d_quality_20261001_refs.json` 与 `hyper3d_quality_20261001_edits.json`。
2. 用 Hyper3D 生成，显式指定 tier、mesh_mode、quality_override；不要依赖网页上一次留下的默认值。原 GLB 和请求记录保存在 `art/models/raw/<ID>_<来源>/`，不要覆盖原稿。
3. 检查形体、前后朝向、缺口、支撑面和文字。文字尽量独立：门楼继续使用 Label3D，黑板则编辑原 UV 图集并在游戏里看两面。
4. 为游戏制作低面数版本。复杂 Raw 模型重新展 UV，从高模烘焙无光照底色，处理 UV 外的空白和接缝；不能直接把一百万面的稠密 UV 当成低模图集。`game_export.py` 的 rebake 分支执行这一步。
5. 保留旧物件的物理占地。`fit_bounds_blender` 在减面后拟合实际有面的网格，先删除未被面引用的孤立顶点，避免 glTF 导出丢弃孤立顶点后缩小约两厘米。三件物体的边界误差已控制到浮点精度范围。
6. 跑 `model_quality_check.py`、`level_check.py`、Godot import、相关测试和真实游戏截图。原模型的三项质量检查先失败，新模型通过。检查脚本能防止退回纯色烤箱、平板瓦面或叠块屋顶；画风和外观仍以截图为准。

```bash

# 使用已经配置的 Hyper3D OAuth 连接，不切换账号或计费空间。
python3 art/tools/rodin_asset.py \
  --refs art/references/hyper3d_quality_20261001/yagura_front_right.png \
         art/references/hyper3d_quality_20261001/yagura_back_left.png \
  --mesh Quad --faces 50000 --tier Gen-2.5-High \
  --out art/models/raw/example_yagura

# 等待被打断时，用已有 generation_id 恢复，不要重新提交付费生成。
# rodin_asset.py --resume <generation_id>，其余参数沿用原记录。

/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup \
  -P art/tools/game_export.py -- art/models/game_assets.json P_farm_gate P_yagura P_deck_oven
/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup \
  -P art/tools/model_quality_check.py -- game/assets/models game/assets/models/_stats/_quality.json
/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup -P art/tools/level_check.py
```

## 放大后的建筑为什么看起来变差

等比放大不会改变长宽高比例，却会降低每米的贴图像素和几何细节密度。不能把所有问题都叫作拉伸：窗框原本歪、屋瓦原本碎，放大只是让缺陷更容易看见。先记录游戏里的尺寸、近景和背面，再决定重做网格还是重绘贴图。房屋的一张 2K 图集覆盖四面墙、屋顶和附属物，不能等同于一面墙有 2K 清晰度。`model_audit.py` 报告按世界面积加权的 UV 像素/米，数值只用于定位，最后看游戏近景。

建筑先定占地、层高、门窗位置和正面，再生成参考图。使用相对一致的正面及背面参考，不把同一物体画成两种屋顶。房屋优先试干净的 Quad 网格与明确目标面数；足够的面数用于瓦片、窗框、栏杆，避免微小噪点吃掉预算。减面后重展 UV、烘焙底色；重新导出时检查边界、入口、店面橱窗和平地。保留旧占地并不代表可以任意非等比缩放，新原稿长宽高比差异太大时应先修参考或换稿。

材质去金属度必须断开连到 Metallic、Roughness、Normal 的旧 PBR 贴图。仅给输入写 0 和 0.92，连接着的 ORM 图仍覆盖数值，游戏里仍会发亮。当前导出器已断开这些连接；`matte_glb.py` 可修复已有 GLB 的材质，并验证节点、网格、UV、骨骼与动画字节不变。

## 减面前必须恢复几何连接

GLB 会在 UV 接缝处分裂同位置的顶点。即使 OBJ 导出时关闭 UV，这些重复顶点仍可能保留；直接减面会把每个图块当成开放边缘去坍缩。本轮门楼和烤箱原稿的开放边比例都是 0，旧游戏版却为 52.46% / 48.22%，不是 Hyper3D 原稿本来破碎。修正 `meshlab_decimate.py`：先在不带 UV 的几何副本上精确合并重复顶点，再清理孤立点、减面、重新展 UV，从未改动的带贴图高模烘焙底色。重新导出的开放边比例为 0.06% / 0.01%。

不能把“weld=0”理解成完全不恢复几何连接。它用于避免在带材质高模上做有距离的合并，防止叶子和细杆被粘住。减面的纯几何副本合并完全重合的顶点是另一件事。连通分量和开放边检查也必须区分实心道具与植被、组装式家具：叶片本来是开放面，独立桌腿本来是多个零件，不能套实心模型的阈值。

## 从高质量设计图生成整屋与近景模块（2026-10-02）

用户否决了随后以 Blender 程序重建主体的房屋方案：即使增加道具与直线构件，整体仍与高质量概念图相差明显。因此不能把 408 项回归和几何守卫通过写成美术验收通过，程序建筑版本没有发布到默认 ZIP。

新的奶奶家样件直接使用高质量图片作为 Hyper3D 输入。先从住宅概念图左半边编辑出干净背景、完整轮廓的单栋参考，再由同一张定稿编辑背右视图与独立缘侧门廊。参考图保留瓦当、檐下、雨管、滑轨、纸门、窗框和木板等明确细节，去除庭院与其他建筑，避免整个场景被合成一块。生成参数统一为 Gen-2.5 High、Quad、50,000 目标四边面；整屋输入正反两图，门廊模块输入独立单物体图。第一张图用于材质生成，不能靠给整屋增加几张图就认定各面各有一张高密度贴图。[官方 Gen-2.5 输入说明](https://docs.hyper3d.ai/en/api-specification/rodin-gen2-5)

模块化的目的，是把近景门窗、门廊、屋顶等部位单独设计和生成，使每块拥有更集中的几何与贴图预算。生成前应统一人尺度、屋顶坡向、颜色与连接面；连接处放在梁柱后、檐下或其他能合理遮住接缝的位置。装配时使用共同原点与等比尺寸，不能把不同形状的模块硬拉伸到同一框里。BANG 可以把已有模型分开供编辑，但不会自动补回原稿缺失的细节，分块后的总面数也需要重新确认。[官方 BANG 说明](https://docs.hyper3d.ai/en/api-specification/bang)

样件任务与对应图片、参数记录在 `art/models/raw/H01_hyper3d_modular_trial_20261002/whole/` 和 `engawa/`。整屋任务为 `216eb45f-4e4e-4d8a-b4bb-5bdacc9b2bbd`，缘侧为 `2ebbb664-4cb4-49a7-84c1-04baaf1b3ccd`。参考图在 `art/references/architecture_hyper3d_modules_20261002/`，完整提示词在 `art/manifests/prompts/architecture_hyper3d_modules_20261002*`。当前连接提供 MCP 的 High、Raw/Quad 和面数控制；直接 API 的高级参数不能冒充已设置。现有 OAuth 对直接 API 的只读请求返回 401，继续使用原账户可用的 MCP，未切换账号或重新创建凭据。

先以原始模型按统一人尺度进行四面和彩色/灰模近景预览；不先减面，不做非等比缩放，不凭面数或贴图边长认定合格。`art/tools/rodin_trial_render.py` 只生成诊断图，不修改原稿和游戏模型。整屋与门廊质量比较通过后，才考虑连接主体并扩展其他建筑。计划、任务记录和预览证据在 `evidence/architecture_hyper3d_modules_20261002/`。

实际试验又增加了独立门窗。整屋和门廊分别约 9.78 / 9.82 万三角面，2K 底色图按 7 米 / 3.5 米的人尺度折算，面积加权的贴图密度中位数约 70 / 113 像素每米。分离门廊有改善，但细格子仍主要体现在贴图，灰模中不充分，不能直接定为游戏成品。

门窗参考由同一门廊图编辑，去掉墙、玻璃和纸，使用真正含空隙的透明 PNG。任务 `c604da78-7669-4fd9-877c-a73e3f513944` 使用 Gen-2.5 High、Raw、100 万目标面。它的木纹、边框和细部更清楚，但仍把格子填成了实心蓝色面板；透明图片和文字要求不能单独证明网格有开孔。对上部格子进行 5,893 条 BVH 射线检查，原稿透过率仅约 0.034%。

`rodin_open_lattice.py` 由原始 UV/底色识别 35 块蓝色面板，保留服务生成的木框和材质，只对这些填充处局部开孔，并在焊接 UV 接缝重复顶点后优化网格。`rodin_door_game.py` 继续减至 21,096 三角面，把切面残留的蓝色材质改成木色；图像像素没有编辑。最终门窗仍使用 2K 图，在 2.1 米高度下中位密度约 407 像素每米。开孔射线测试通过；实际彩色和灰模都能看到空隙。原稿、局部修正 `.blend`、优化版 `.blend` 与 GLB 均保留。此门窗组件的改善不能外推为整屋已经通过验收。

这说明需要按可见细节进一步拆：主屋和侧屋确定体量，屋顶及檐口、门廊、门窗各自作为模型，玻璃或障子纸另设表面，道具独立摆放。来源仍由 Hyper3D 承担主体造型，Blender 做局部切孔、少量几何校正、优化和拼接。不要把整屋再次程序重建，也不要把灰模里不存在的细节写成真实几何。
