# 小模型拼接与真实橱窗（2026-10-03）

此前街面橱窗确实是玻璃 QuadMesh 上的室内映射，后墙和货品都来自图片。这轮把五家店的八个底层窗户改成真实开口、浅室内、独立家具和商品。可进入的商店、面包店仍是原来的独立场景；街面陈列室只负责从窗外看进去。

## 素材与拼接

参考图由内置 imagegen 生成，采用动漫线条、哑光色彩和简单背景。小模型通过自建 Pixal3D（RTX 4080）图生 3D；本轮没有新增 Hyper3D 积分。已有房屋主体仍来自 Hyper3D，Blender 负责裁切、定尺、转正、减面与贴图烘焙。

| 模型 | 使用位置 |
| --- | --- |
| W01 花桶组合、W04 向日葵、W05 绣球、W06 百合 | 花店前台、后排花架与高处壁架 |
| W02 商品架、W09 米袋、W10 瓶筐 | 商店后排与窗前台面 |
| W03 整条黄瓜筐 | 店外两个倾斜菜台，替换原来的绿色圆片 |
| W07 甜面包、W08 法棍篮、W12 空木托盘 | 面包店三层陈列架和门窗内侧小台 |
| W11 青花茶具 | 杂货屋台面，后排保留立体碗柜和商品架 |
| T02 夏季乔木、T03 圆冠树、T04 细杉树 | 镇边、回农园小路与农园外缘 |

邮局复用原有书架和包裹模型。每件商品经 `WorldBuilder.spawn()` 创建，保留 `model_id` 和真实网格；货架、地板、墙面、腰板、窗台和内侧窗框是按米搭出的结构。橱窗使用 `shop_glass.gdshader`，只画透明玻璃与少量天空反光，不采样商品图片。每家店有实际 OmniLight，傍晚提高亮度。

镇边有 38 棵新模型树，三种轮廓按固定随机种子混合，改变旋转和等比尺寸。农园外缘十二处和上坡三处也使用新树形。远山、屋顶线和农园的远处树林仍是绘画背景；靠近镇子边墙的树卡片已经替换。

## 这次试出来的经验

1. **先拆语义，再生成。** “装有面包的托盘”试了两版，Pixal3D 都只保留面包。第二版参考图让面包色块更清楚，但没有解决托盘丢失，所以另做空托盘，和面包拼起来。复杂店内陈列不要一次生成整面商品墙。
2. **参考图要让底座可见。** 用简单背景、完整底部、适中的俯拍角度；花盆、瓶筐和托盘的轮廓要与背景分开。文字独立制作，透明玻璃不交给生成服务猜测。
3. **朝向和贴地分别校正。** 生成服务会保留参考图的相机倾角。矩形底座先量站立面，再量正面方向，使用刚性旋转和等比缩放。花盆按底部 28% 的高度测支撑面，避免花叶的凸包主导倾角；树冠不能当作树根的站立面。
4. **保留原始结果。** 每次任务保存参考图、seed、resolution、job ID、状态和原 GLB。受理后只查询同一 ID，不重新提交同一任务。服务最多排三个任务，429 表示队列满，等空位再提交未受理的任务。
5. **完整网格不等于高面数。** 本轮原稿约九十万至百万三角面，游戏版小物件约一万至两万多面、2K 贴图。重拓扑后从原稿重烘焙颜色，不能只删顶点而继续使用错位 UV。必须同时看彩色和灰模，以及背面。
6. **旧房屋不一定是封闭实体。** 在有洞、薄片和藤叶的生成网格上连续做布尔，会出现切面残片，甚至删掉大块外墙。`mesh_cavity_clip.py` 直接裁切三角形并插值原 UV，不生成布尔封口。操作前后检查外部包围盒和保留面数，避免把错误网格导出进游戏。
7. **窗台决定近景是否可信。** 新商品放进去后，还要清理挡住它的旧网格、补实际窗台和内侧窗框。陈列台留在玻璃内侧，避免木台穿出门面。正面、斜侧面和夜间都要看。
8. **导入完成后再验收。** 新 GLB 导出后先等待 Godot import 真正结束，再启动截图或测试。未完成的导入会让运行场景继续用旧缓存，甚至缺少刚生成的模块。

来源清单为 `art/manifests/models_pixal_windows_20261003.json`。参考图及提示词位于 `art/references/windows3d_20261003/`、`art/references/window_modules_20261003/` 和 `art/manifests/prompts/`；原稿在 `art/models/raw/*_pixal_*_20261003/`。五栋开窗源文件在 `art/models/raw/window_cavities_20261003/`，导出配置仍为 `art/models/game_assets.json`。

## 验证与发布

八个开口各有 117 条射线检查实际净空；商品体积、房间进深、玻璃材质、夜灯、树形、树卡片、黄瓜筐和玻璃内侧余量由 `--only=display` 检查。旧场景在最终的 19 项检查上全部失败，新场景另做全量检查。整栋贴图密度仍要求 200 px/m，公寓住户模块仍要求 280 px/m，结构直线误差仍要求小于 6 毫米。

近景、原稿灰模、回归日志和最终发布记录集中在 `evidence/windows3d_20261003/`。发布状态以该目录的 `verification.json` 为准；只有全量检查及解压后的原生应用完整演示通过，才更新 `builds/HareMachi.zip`。

本轮完成 15 种独立素材、16 次生成（甜面包两版，空托盘单独生成），冻结工程 500 项检查全部通过。解压应用 20 张近景通过，原完整演示 111.46 秒、模拟 1227.2 秒、44 张截图、Q05 完成、退出码 0；SQLite quick_check 为 ok，两个 v4 快照的 SHA-256 均匹配。Apple Silicon / Intel 架构、深度严格代码签名和 ZIP CRC 通过。默认包已经原子更新，日期包为 builds/HareMachi-windows3d-20261003.zip，1,435,149,970 字节，SHA-256 为 cf49f61e31c03bf630610e5d6498b674607cf99515a77f877dbdbecd10464ba4。旧包保存在 builds/HareMachi-before-windows3d-20261003.zip。退出时仍有此前版本相同的一条 shader RID 提示；没有 SCRIPT ERROR。完整结果见 verification.json。
