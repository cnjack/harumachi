# 澪手臂厚度与动作节奏（2026-10-21，v12）

用户指出 v11 手臂过细、动作不灵动且慢。v11 的连接带检查通过只说明所测接缝未露底，不能代表比例和动作节奏被接受；本轮修正源素材注册和源动作，并重新导出正式 Cubism 资源。

## 粗细与轮廓

继续使用已有 `art/live2d/mio/articulated/arm-segments-20261021.png`。原画有足够衣袖厚度，问题来自 `pack_assets.swift` 把横向比例压到上臂 0.85、下臂 0.20。现在分别为 1.25、0.28，纵向骨段与肩肘腕锚点不变，所有手型的腕部轮廓重新匹配公共前臂。

从实际 PNG alpha 垂直于骨轴量得：上臂中部由 30.5–31.25 增至 45.5–45.75 像素，下臂衣袖由 31.25 增至 43.5，裸露前臂由 12.5 增至 17.5。加宽约 39%–49%。肩根前 28 像素保留窄的隐藏边缘，再渐变至上臂完整宽度，消除第一轮抬臂复拍中露出的双层圆片。

源布局更新为 `20261021-articulated-v12`，32 层源 PSD、34 层 Cubism PSD、CMO3、图集和五套 motion3 同步。MOC 骨架结构未改，仍为 24 参数、34 ArtMesh、Cubism 4.0 目标（MOC version 3）；宽度修订已经写入源像素和导出图集。

## 动作节奏

| 动作 | 本轮修订 |
| --- | --- |
| 放下 | 保留胯侧垂手；退出手势的回落更快，腕部轮廓加宽后与前臂连续 |
| 招手 | 起手 1.35 → 0.55 秒，肘部摆幅增加，手腕延后跟随，肩膀、头部与躯干作小幅响应；频率约 0.88 → 1.37 Hz |
| 伸懒腰 | 起手 1.5 → 0.85 秒，先握拳再抬起；左右肩肘略错开，舒展保持中有轻微屈伸，回落 1.5 → 0.85 秒 |
| 思考 | 起手 0.85 → 0.48 秒，保留食指抵下巴求解与歪头；思考云提前跟随实际接触，落臂保持安全路径 |
| 说话 | 起手 0.85 → 0.48 秒，前臂分拍展开，手腕、头部与另一侧手臂错开响应 |
| 手动切换 | 轨迹速度上限 480 → 850 源像素/秒，最短过渡 0.55 → 0.30 秒；相反折肘方向仍先经过垂手 |

所有动作末尾回到垂手，持续时间和自动循环窗口保持原值。正式窗口和本地预览为 60 FPS；动画使用真实秒数，避免通过帧数让高刷新率机器播放更快。全组离线取样保持 30 FPS，另用现有显示器验收实际帧率。

## 验证

证据目录：`evidence/mio_arm_energy_20261021/`。新增 `ArmEnergyTests` 对 v11 先运行，4 项测试出现 12 处失败，捕捉过窄源纹理、迟缓起手和招手幅度不足。测试包含实际源 alpha、点击至抬手的延迟、30/60 FPS 时钟一致性；已有 Core 每帧骨段、关节、下巴接触和手型检查继续保留。

最终统计与逐组结果见同目录 `verification.json`。视觉复核需看五套动作肩肘腕放大图、全部切换、视线极值、完整自动周期及说话中断；宽度和中心点通过不能替代轮廓与节奏检查。当前测试静音，不启动系统监控、Inbox、网络或虚拟显示器。

- 43 项 XCTest：41 通过，2 项 HTTP 测试跳过，无失败。官方 Core 每帧骨段、关节和下巴接触检查通过。
- 全组 6514 帧、781680 个连接带像素，最小 alpha 253/255，无失败；最大 Core 接合误差 0.000137 像素。13028 条皮肤带最大暗线亏损 1.91（阈值 4），无失败、无裁边。
- 实际 PNG 序列中，招手手腕上升至 y<290 从 1.20 秒降至 0.63 秒，点击垂手→招手从 1.30 秒降至 0.77 秒；伸展手腕达到 y<200 从 1.30 秒降至 0.73 秒。均使用相同 30 FPS 和画布坐标测量。
- 已逐项查看五份关节表、五份全切换表、视线极值、自动/说话中断、长时钟和自动环回。24 秒同时间轴前后对照 `motion-comparison.mp4` 已完整解码。
- 用户解锁后，现有屏幕原生窗口在 28.16 秒内渲染 1613 帧，平均 57.28 FPS（目标 60，验收下限 50）。放下、招手、伸展、思考、说话及自动六状态全部通过，逐状态 PNG 与自身窗口图已查看。完整记录为 `window-final/native-window.json`。
