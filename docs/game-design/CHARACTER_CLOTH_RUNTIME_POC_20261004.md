## 这一轮的判断

**近期优先继续“原修形 + 有限幅的袖口辅助骨”。** 它保留原材质与动作，局部摆动比较轻，控制成本低。GPU 布料已在本机 Metal / Forward+ 上运行，但在当前生成网格的袖口仍能看到不均匀褶皱和细小边缘变形。不能把插件能运行当成人物质量已经合格。

本轮只增加袖口局部次级运动，没有修复整个肩部、腋下和肘部的面流。三列仍共享原来的肩袖轮廓和主体动画；改善幅度有限，整体建模质量、步态与跳舞自然度不作为本轮已完成事项。完整换装还需要连续身体、衣物拓扑、权重和身体遮罩。RWT、PSD/RBF、UniRig / SkinTokens 本轮没有执行。

## 三组的具体结构

| 项目 | 原 13 对照 | A：弹簧骨 | B：GPU XPBD |
| --- | --- | --- | --- |
| 可见外表面 | 原三角形与 UV，拆出左右袖片 | 同左 | 同左 |
| 骨骼 | 原 54，含 30 根手指骨 | 原 54 + 12 袖口辅助骨 | 原 54 |
| 姿态修形 | 左右肩、左右袖口共 4 个，原动画驱动 | 同左 | CPU 将修形增量送入 GPU 蒙皮目标 |
| 局部物理 | 无 | 四条三关节骨链，原生 SpringBoneSimulator3D | 两件袖片，GPU XPBD 距离与弯曲约束 |
| 碰撞 | 无 | 上臂、前臂胶囊代理 | 每袖 2 个胶囊代理，自碰撞关闭 |
| 限幅 | 原修形 | 辅助骨局部转角最多 12° | 模拟及渲染位移预算：空 8 mm、澪 12 mm |
| 蒙皮影响数 | 4 | 袖片最多 8，保留原权重 | 4 |

袖口内侧新增小段身体填补可见空隙，取原手臂的贴图颜色；这是局部补面，并不是完整裸体身体。原袖片拆分使用服装颜色、骨骼影响和手臂位置筛选，不是完整服装版型重建。

弹簧参数为 stiffness 12、drag 0.70、gravity 0.30；切动作时 reset，复位使用骨骼原 Rest rotation。辅助骨后的 SkeletonModifier3D 将最终转角限到 12°，不改原动作骨骼。原生求解在连续动作中曾出现超过 100° 的局部辅助骨转角，因此不采用无限幅版本。

GPU 参数为 3 子步、4 次迭代、stiffness 0.98、bend stiffness 0.65、damping 0.985、max speed 2。只有袖口末端约 5–6 cm 从固定区渐变到模拟区，肩缝保持原动画。

## 实测发现及迭代

| 阶段 | 发现 | 处理 |
| --- | --- | --- |
| 基础 GPU 演示 | 本机 Metal 计算管线可运行；退出时 RID / 材质资源释放报错 | 在隔离插件副本中调整释放顺序、先移除材质引用 |
| 分离袖片与补身体 | 最初的内部手臂管太粗，露出袖子 | 缩小半径，只补袖口附近重叠段 |
| 弹簧初版 | 不启用模拟时也会拉开袖口 | 查到 Godot 4 的 Pose 包含 Rest；不能将辅助骨旋转直接置为单位四元数 |
| GPU 初版 | 位移很小仍出现表面裂纹 | 去掉仅在背面分支写 DEPTH 的材质逻辑；Godot 要求所有分支一致写深度 |
| 碰撞接入 | 未指定类型的 NodePath 数组没有应用到导出属性，实际碰撞数为 0 | 使用 Array[NodePath]，日志与运行时确认每袖 2 个代理 |
| 固定肩缝 | 碰撞目标投影会移动固定区域 | 固定区域不投影，过渡区域按模拟权重投影 |
| 第一段录像 | GPU 袖口细小毛刺，直接重建渲染表面影响原层次 | 改为“原生蒙皮表面 + GPU 位移”，邻域平滑位移，保留原修形法线并限幅 |
| 资产回归 | 增加辅助骨后压回 4 个影响，静态误差约 5–10 mm | 袖片导出 8 个影响；静态最大误差降到 0.1 mm 内 |
| 连续动作 | 辅助骨偶发大转角 | 加 12° 输出限幅；重录两个人物并检查 30 / 60 固定步长 |
| 录像检查 | 双重等待帧信号会拉长章节；招手指尖靠近标题 | 章节按 process_frame 计数；抬手镜头上移，避免文字盖住手掌 |

早期失败截图和第 7–10 版录像均保留在证据目录。最终文件使用 `*-final.mp4`，不用早期录像作为验收结果。

## 验证结果及边界

- `asset-contract.json`：四个输出全部通过。空 96,169、澪 94,355 个原三角形的可见位置与 UV 保留；贴图字节相同；原骨骼动画曲线误差为 0；原 11 个动作时长误差为 0；无非法关节索引或未归一权重。
- `rig-regression.json`：旧单位四元数复位失败，袖片最大误差为空 71.60 mm、澪 51.05 mm；修正并保留 8 个影响后分别为 0.088、0.093 mm。160 次采样 / 角色。
- `palms.json`：原实际掌面法线检查保留，832 次采样通过。行走、跑步等自然垂手时朝向人体。
- `runtime-audit.json`：两个角色在固定 1/30、1/60 秒步长下，检查 11 个原动作及参考 T pose，每动作 4 个相位、两只袖子，共 384 份 GPU 缓冲采样。位置均有限；固定区域误差最大 0.1371 mm；实际模拟位移在 8 / 12 mm 预算内；辅助骨输出不超过 12.02°（含浮点容差）。
- 各录像 `native.log`、`recording.json`：Godot 4.7.2、Metal、退出码 0，MP4 帧数和尺寸通过。录像内的 CPU/GPU render time 不能当完整布料性能测量；本轮未做生产性能基准。

胶囊代理、有限值与位移限幅不等于逐三角无穿模，也不证明新舞蹈、整件衣物或全身换装已经通过。GPU 显示法线保留原修形法线，适用于本轮毫米级位移；更大布料形变还需一致重算法线和正式动漫着色器接入。

通用 `level_check.py` 已对隔离 GLB 运行，结果写 `level.json`，没有更新正式游戏 `_stats`。完整蒙皮人物凸包选出的支撑面不能直接当鞋底，约 37° 的结果不作为人物倾斜验收。本轮原脚部几何与动作保留；正式集成仍需游戏地面、脚锁定及接触检查。

## 源码、许可与复现

工程在 `art/poc/character_cloth_runtime_20261004/`，证据在 `evidence/character_cloth_runtime_20261004/`。本轮所有插件改动只作用于该隔离 Forward+ 工程。

GPU 插件来自 [alien-life/gpu-cloth-sim](https://github.com/alien-life/gpu-cloth-sim)，保留 MIT LICENSE；源码归档摘要、六个修改文件和差异在 `vendor/provenance.json`、`vendor/local-changes.patch`。本地 GPU 输出纹理已改为位移，接口与上游 v3.0 的绝对位置纹理不同，不能将这份 shader 单独混用到原插件。Morph adapter、袖片准备、限幅和对照驱动为本地 POC 代码。

深度写入规则见 [Godot spatial shader 文档](https://docs.godotengine.org/en/4.7/tutorials/shaders/shader_reference/spatial_shader.html)；原生弹簧骨的碰撞、reset 与缩放约束见 [SpringBoneSimulator3D](https://docs.godotengine.org/en/4.7/classes/class_springbonesimulator3d.html)。

```bash
python3 art/poc/character_cloth_runtime_20261004/audit_assets.py
python3 art/poc/character_cloth_runtime_20261004/check_runtime.py
python3 art/poc/character_cloth_runtime_20261004/record_comparison.py --tag final
```

启动器可直接双击；← / → 切动作，V 切正侧背面，空格暂停，Esc 退出。窗口必须保持可绘制，录像与有窗口的检查按顺序运行。

## 下一轮应解决什么

先整理独立袖管、肩缝与腋下拓扑，并补连续身体，再做稳健权重转移和多个姿态的修形对照。给自由衣片建立更规则的低面数模拟代理，与原高面数表面建立形变映射；本轮的密网格焊接和平滑位移还不等于这一步。这样能保留人物脸、头发和服装设计，同时提高肩肘质量，为换装及新舞蹈留下可维护的资产。
